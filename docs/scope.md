# V1 scope

## Purpose

The Knowledge Platform investigates whether upstream agentic knowledge preparation can reduce query-time complexity and latency for previously unseen multi-hop questions while preserving answer quality. A second research question asks whether useful agentic preparation needs a purpose-built architecture or whether a capable generic preparation harness can achieve comparable results. Both are hypotheses to evaluate, not demonstrated results. League of Legends was selected as the experimental domain for its large, evolving, interconnected knowledge space, multi-hop relationships, overlapping sources, and substantial public unstructured educational material. Additional sources can inform incremental knowledge preparation; building a League application is not the primary technical purpose.

This repository currently builds the acquisition and knowledge-preparation side. Implemented Source Acquisition reaches transient selection outcomes through English transcript acquisition, absolute semantic assessment, deterministic quality gating, and comparative selection only when needed. Resumable runs pass the selected source directly to Bronze and register it only after durable validation. A separate explicit operation cleans persisted Bronze into durable Silver using deterministic NFC/whitespace normalization. Semantic logical segmentation produces durable sections through a separate explicit API. Standalone LLM extraction proposes transient KnowledgeItems from one validated CONTENT section. Section validation publishes durable accepted-section checkpoints, and source audit consolidates them into canonical one-source knowledge with preserved conflicts and exact lineage. The pure Gold contract now defines stable identities, source-item references, historical merge links and deterministic in-memory validation/serialization. Canonical Gold Markdown/metadata pairs and local snapshot persistence are implemented separately. Semantic Gold integration and retrieval indexing remain planned. A separate Voice Coach may later retrieve the prepared knowledge and reason over game context supplied by the player; its application and evaluation remain separate from the knowledge-preparation experiment.

V1 is an incremental, local-first system rather than a fixed source corpus. Its initial acquisition targets are all Champions in a versioned, machine-readable local catalog. There is no Champion × Role target matrix: role-specific guidance and reusable general concepts may emerge from selected sources and be represented in Gold. Systematic acquisition for general-concept targets is future scope.

## Source responsibilities

Riot Games Data Dragon establishes the authoritative Champion target catalog / target universe. The repository loads the committed versioned artifact locally without a runtime Riot request. This structured target source is not the main knowledge corpus. YouTube is the V1 public source pool: relevant educational knowledge is primarily in unstructured video/transcript content, with structured metadata used for discovery and ranking. Knowledge preparation starts from that source material, not a pre-structured knowledge base.

## Included in V1

The following is the accepted V1 target scope, not an inventory of delivered functionality. The [current implementation](../README.md#current-implementation) lists the available components through explicit source audit and durable SourceKnowledgeArtifact. The Gold model/codec and document persistence are available independently. Semantic Gold integration, broader operational state, indexing and knowledge-change measurements are not yet implemented. Transient extraction proposals are not accepted knowledge; validated section checkpoints must all be present and compatible before source audit. Source-level knowledge remains separate from GoldKnowledgeUnit and later cross-source Gold integration. The contract supplies global identity primitives and document storage preserves them; neither creates Gold units from sources automatically. Empty Gold is valid; empty canonical topics/documents are pruned without deleting knowledge or historical merge records.

- **Repeated acquisition:** Manually initiate a logical run that attempts all configured Champion targets. Each run keeps its original catalog context and full target data across resumes. The implemented service integrates at most one source per target/run and stores progress, with a shared budget of at most three active target attempts and target-level failure isolation. The same attempt directly invokes Bronze integration and records `INTEGRATED` only after registration succeeds; downstream knowledge curation remains planned; no target is permanently complete after a source count or run.
- **Source acquisition and quality-controlled selection:** Seek 20 unique unseen YouTube candidates per target where available, excluding integrated source IDs and refilling as needed. Apply duration eligibility, then deterministic popularity/recency ranking to return up to three candidates. Acquire available English transcripts transiently. Stage 1 semantically assesses each transcript against an absolute minimum standard and returns structured attributes. Application code derives PASS only when target relevance, educational substance, and transcript usability are true and noise does not dominate. Zero PASS yields normal `NO_SELECTION`; one PASS is selected directly; two or three PASS enter a separate comparative LLM call. Only the selected source is handed to Bronze; the full payload remains transient until Bronze persistence. Normal search exhaustion is not a technical run failure; normal absence of a usable source is persisted as `NO_SELECTION`.
- **Bronze and Silver:** Preserve the admitted source's raw transcript and available provenance in immutable Bronze. Implemented Silver cleaning performs only Unicode NFC and whitespace normalization, preserving repetitions, unusual wording, original segment order/indices, timing and Bronze provenance. Cleaning removes no advertisements, sponsors or filler. The single semantic SEGMENT stage then proposes contiguous logical boundaries and CONTENT/ADVERTISEMENT kinds over indivisible existing segments. Deterministic validation enforces complete exactly-once ordered coverage, with at most three semantic/provider attempts and no section-size rules, generated titles/summaries or fallback chunking. Clear ads are marked and durably retained; mixed or ambiguous substantive material remains CONTENT. All-empty valid Silver yields durable NO_SEGMENTABLE_CONTENT, a terminal non-extraction outcome. Extraction consumes validated CONTENT sections without segmenting again and proposes high-coverage source-grounded knowledge; semantic acceptance remains downstream. Silver does not synthesize League knowledge or impose a semantic ontology.
- **Knowledge curation:** A Knowledge Curator inspects relevant existing Gold knowledge while processing one selected Silver source at a time. Gold is the canonical, versioned Markdown Knowledge Wiki with an adaptive structure, source provenance, and preserved contradictions. The curator may make no change, enrich, rewrite, create, merge, link, or flag a conflict; it does not autonomously delete knowledge in V1.
- **Local state and retrieval:** Local SQL state tracks integrated sources, run progress and per-target outcomes, raw knowledge-change counts, and index synchronization. A local retrieval/vector index is derived from Gold and updates changed documents incrementally, including removal of stale vectors where applicable. It is a serving layer, not the source of truth.
- **Knowledge-gain evaluation:** Compare raw per-run/per-target counts of new, enriched, rewritten, and merged concepts; links; conflicts; created or updated Wiki pages; and no-change integrations where applicable. V1 does not require a synthetic aggregate score or an automatic stopping threshold.

The V1 design uses local Bronze, Silver, and Gold files, local operational SQL state, and a local retrieval index. External source/search and LLM APIs are used where needed. Azure infrastructure, including Azure AI Search, is not required for V1; Azure remains a possible future deployment target.

Neither semantic selection stage receives popularity, recency, scores, discovery order, or original shortlist rank. The comparative stage receives only passing transcripts and no Stage-1 assessments, booleans, reason codes, or rationales. Full transcript content and original identity/timing remain available; technical selection failures produce `SELECTION_FAILED`, distinct from normal `NO_SELECTION`. Selection does not perform persistence or register integrated sources.

## Incremental acquisition and knowledge evolution

Already integrated IDs are excluded from later candidate collection. **Selected** means chosen by the selection operation; **integrated** means the Bronze API has successfully persisted the selected source and registered it in the catalog. Selection alone does not make a source integrated. Lookup/registration, separate resumable run state and end-to-end Bronze integration exist. Selected identity is reconciled before retry: already registered durable Bronze allows free state repair; missing registration or Bronze requires a bounded active attempt from the same three-attempt budget. Run schema v1 requires an explicit backed-up migration to v2. Bronze preserves one immutable artifact per global video ID, with the original integration provenance; later compatible target/run contexts do not rewrite it. New runs use the then-current catalog; existing runs retain their copied targets and totals even after catalog changes or removal of the original file.

In the intended repeated-run flow, one run may integrate Source A, a later run excludes A and may integrate B, and another excludes A and B while seeking C for the same Champion. The implemented run service coordinates successful Bronze persistence and registration; run selection alone does not exclude a source. Additional sources need not add useful new knowledge: planned curation may create, enrich, identify overlap, flag a conflict, or make no change after inspecting existing Gold. Persistent knowledge is intended to evolve over time instead of being rebuilt independently for each source. General concepts may emerge from Champion sources; this does not add concept-target acquisition to V1.

## Future comparative evaluation

| Planned system | Preparation and role |
| --- | --- |
| Purpose-Built Agentic Knowledge Preparation | This repository's complete custom system: unstructured sources → acquisition → Bronze → cleaned Silver → semantic segmentation → extraction → semantic validation → source audit → cross-source Gold integration → canonical Gold → downstream retrieval/answering. The complete system is not yet implemented. |
| Fixed-Size RAG | Conventional fixed-size chunking and standard retrieval over the same controlled source corpus; a simple preparation baseline. |
| Generic Agentic Preparation | A capable general-purpose agent receives the same controlled corpus and a broad knowledge-base-building objective. It may inspect sources, organize/update documents, consolidate information and improve its knowledge base iteratively. It does not receive this project's specialized contracts or preparation architecture. Hermes is a candidate harness, not a mandatory dependency. |
| Live Web Search Agent | A capable agent answers the same evaluation questions using live web search, without a dedicated prepared knowledge base. |

| Comparison group | Planned systems | Purpose |
| --- | --- | --- |
| Controlled knowledge-preparation comparison | Fixed-Size RAG; Generic Agentic Preparation; Purpose-Built Agentic Knowledge Preparation | Isolate preparation strategy using the same curated source corpus and the same previously unseen multi-hop questions. |
| Practical system-level benchmark | Purpose-Built Prepared Knowledge System; Live Web Search Agent | Test the practical value of maintaining prepared knowledge versus searching the open web at query time. This is not a controlled preparation ablation. |

Where possible, the later controlled comparison should hold the answering model, questions, source corpus and applicable downstream retrieval infrastructure constant. The generic preparation agent must not inherit the custom KnowledgeItem contract, section-validation gates, exact source-audit lineage accounting, IntegrationPlan or specialized Gold integration rules: doing so would reproduce the architecture under test.

Live Web Search changes the available information universe, source selection, retrieval mechanism, freshness and potentially source quality. It is a practical system-level benchmark and must be analyzed separately from the controlled same-corpus comparisons.

The active implementation priority remains completing Source → canonical Gold integration. Retrieval/Answering, Baselines and Experimental Evaluation follow as separate downstream workstreams; no baseline or evaluation implementation is added to the active Core Pipeline scope. The deployed acquisition system may grow incrementally, while the controlled experiment will use an explicitly curated shared corpus.

The later Baseline / Evaluation design freeze will decide chunk size and overlap; embedding model and vector store; reranking; Web Search provider/tool; generic-agent harness and prompts; tool/token budgets and search-call limits; evaluation questions and ground-truth/required-evidence construction; metric definitions and weighting; statistical tests and repetitions; and latency/cost measurement protocol. None is fixed by this framing update.

No experimental results or latency reduction are established. Existing raw knowledge-gain requirements remain part of the accepted target scope and are not completed evaluation results.

## Outside V1

- Systematic general-concept or dedicated Champion Matchup target acquisition. Such knowledge may still emerge from Champion sources and be represented in Gold.
- Automatic patch tracking or knowledge invalidation after game updates.
- Automatic scheduling, event-driven ingestion, or distributed workers.
- A fixed Champion × Role target matrix, fixed source quota, permanent Champion-completion state, or automatic marginal-gain stop threshold.
- A mandatory fixed Gold ontology, semantic labels on Silver chunks, or autonomous destructive deletion of Gold knowledge.
- Automatic live game-state reading; the player supplies relevant context.
- Persistent cross-game user memory. The separate Voice Coach may maintain current-game session state.

The [architecture](architecture.md) describes the flow and the [ADRs](adr/001-medallion-architecture.md) record the decisions and their history.
